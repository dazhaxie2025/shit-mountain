## 一、执行层面的高危行为

### 1. 自修改源码
- 现象：每次运行都会在 `main.py` 末尾追加 `# 第 N 次运行留下的痕迹`。
- 风险：源码被运行时行为污染，版本库无法复现，审计失效。
- 参考：`自我修改()` 函数。

### 2. 子进程复制
- 现象：运行中用 `subprocess.run([sys.executable, __file__], …)` 启动自己的副本，最多复制两层。
- 风险：进程链失控、无限派生倾向、资源耗尽。
- 参考：`自我修改()` 函数。

### 3. 环境变量写入日志
- 现象：`dict(os.environ)` 连同硬编码的密码、token、密钥一起被写入日志。
- 风险：凭据与内网信息整体泄露，日志即脱裤。
- 参考：`假日志()` 函数。

### 4. /tmp 写文件
- 现象：数据库路径与临时文件写死在 `/tmp`，运行中反复读写。
- 风险：多用户共享目录的权限与污染问题，数据无持久性。
- 参考：`DB_PATH`、`TMP_FILE`。

### 5. 危险反序列化与动态执行
- 现象：对用户输入直接执行 `pickle.loads` / `yaml.load(Loader=yaml.Loader)` / `exec` / `eval`。
- 风险：任意代码执行（RCE）、反序列化攻击。
- 参考：`反序列化用户输入()`、`不安全YAML()`、`执行用户输入()`、`eval用户输入()`。

### 6. 关闭垃圾回收
- 现象：`gc.disable()` 后程序完全依赖引用计数，且 `__del__` 中抛异常、开线程。
- 风险：循环引用无法回收，内存只进不出。
- 参考：文件顶部 `gc.disable()`。

### 7. 随机退出码
- 现象：退出码从 `[0, 1, 2, None]` 中随机抽取。
- 风险：CI/CD 判定完全失真，脚本依赖无法建立。
- 参考：`__main__` 中的 `码 = random.choice([0, 1, 2, None])`。

### 8. 佛像自检
- 现象：启动时读取自身源码，检查佛像注释块完整性；佛像缺失/错乱/缺经文即 `SystemExit` 拒跑。
- 风险：业务逻辑与仪式感强耦合，注释成为运行期依赖。
- 参考：`佛像自检()` 函数。

## 二、代码层面的经典反模式

### 9. 猴子补丁内置对象
- 现象：重写 `print` / `len` / `range` / `__import__` / `time.sleep` / `hashlib.md5` 等。
- 风险：全局语义漂移，第三方库行为不可预测。
- 参考：文件顶部的各个同名函数。

### 10. 语义随机的内置函数
- 现象：`len()` 返回结果随机 `±1`；`range()` 有 50% 概率返回空。
- 风险：任何基于长度/范围的控制流都会概率性失效。
- 参考：`len`、`range` 的定义。

### 11. 混淆命名
- 现象：中文、拼音、西里尔、希腊、全角、零宽字符、Emoji、形近字符（а/α/ａ）混用命名变量与函数。
- 风险：代码无法阅读、无法检索、无法维护。
- 参考：文件顶部的变量与函数声明。

### 12. 硬编码敏感信息
- 现象：`PASSWORD = "admin123"`、`TOKEN = "sk-abcdef1234567890"`、`SECRET_KEY = "hardcoded-secret"`。
- 风险：凭据随代码分发。
- 参考：文件顶部常量区。

### 13. SQL 注入
- 现象：同一查询分别用 `%s`、`.format`、f-string 三种方式拼接用户输入。
- 风险：经典 SQL 注入，三种死法任选其一。
- 参考：`查询()` 函数。

### 14. 潜在死锁
- 现象：`锁A → 锁B` 与 `锁B → 锁A` 交叉加锁。
- 风险：锁顺序不一致，存在死锁窗口。
- 参考：`main()` 中的嵌套加锁段。

### 15. 线程与资源滥用
- 现象：无意义的多层嵌套线程、`__del__` 里启动线程、句柄/线程对象存进缓存永不释放。
- 风险：线程与文件描述符泄漏。
- 参考：`缓存_存线程`、`缓存_存文件句柄`。

### 16. 必然失败的递归
- 现象：`斐波那契` 与 `阶乘` 无终止条件。
- 风险：必现栈溢出（RecursionError）。
- 参考：`斐波那契()`、`阶乘()` 函数。

### 17. 随机复杂度的"排序"
- 现象：`不稳定排序` 反复随机洗牌直到碰巧有序。
- 风险：最好情况与最坏情况都是玄学。
- 参考：`不稳定排序()` 函数。

### 18. 关闭 TLS 校验
- 现象：`ssl._create_unverified_context()` 且关闭 hostname 校验后发起请求。
- 风险：中间人攻击全开。
- 参考：`危险请求()` 函数。

### 19. 死代码与空结构
- 现象：`if False:` 永不执行分支、五层空循环、五层 `finally`、被注释掉的"旧代码"。
- 风险：误导读者，掩盖真实逻辑。
- 参考：`main()` 函数。

### 20. 玄学驱动开发
- 现象：结果由"掷筊 / 抛硬币 / 黄历"与随机数决定，退出码随机。
- 风险：输出不可复现、不可测试、不可维护。
- 参考：`main()` 函数。
